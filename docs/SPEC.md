## 1. What Kiln 4 is
Kiln 4 compiles the Herdr team way of working (72 h on CT101, 2026-10-26..29) into one Claude Code plugin in `/DEV/kiln` (GitHub kiln, own marketplace). Thin layer over Herdr 0.9.5 + Claude Code + Codex + agy natives. No Teams/Workflow machinery. Concepts migrate, machinery does not.
- Bridge tab (boss names it; default `bridge`): boss (owns the conversation with Fred and relays the agreed brief to its orchestrator; nobody else talks to Fred; **the brainstorm happens here, with the boss** [R], no brainstorm tab) → orchestrator (the boss's manager; owns the whole loop) → helper (plumbing, delegated reads, phase-prep chores, owns the watcher [R]).
- One tab per phase, standing manager each (persistent-mind real session): research → plan → build+review → verify → deploy, plus **council**. Fresh workers in their own panes (never native subagents), silent, bounded packet, result + status file, closed when accepted.
- **Owner-driven ("agent-driven development", Fred 2026-10-29)**: each phase artifact has one persistent owner seat, and *the owner answers, the file remembers*. Whoever needs something from another phase asks its owner with a `question` row (Chunk Master → architect, → build manager, → research; any manager → any owner) instead of reading its files; the owner's `answer` row points at the file section that holds the details, so readers open the file for the details of an answer, and otherwise for the structured parts (Done-when, pinned contracts, ADRs) or when the owner is gone. Files stay the durable record across rotations; they are the owner's memory, not the source of truth while the owner is alive. The per-phase folder separation stays as it is.
- **Addresses**: the ledger `to:` field and every card address a seat by its tab/role (`director`, `super`, `research`, `plan`, `build`, `verify`, `deploy`, `helper`); the display name (Oracle, Robin, Lucius...) is the boss's choice, cosmetic, shown only in the pane label. Chunk Master (Chunk Norris) and Gravedigger keep fixed names.
- **Observer** (Fred, 2026-10-29): **Master Roshi**, an Astra bot of Fred's, watches everything the team does and may, rarely, leave a comment. Read-only, never a Kiln seat, never addressed by cards or packets, no inbox. Seats treat a comment from him as advice to weigh, never as a work order; only Fred's words and the owner chain give orders.
- Kiln itself is spec-driven: per-phase hand-off table (artifact, producing seat, accepting seat, completion evidence) **written before any code** [R]; the operator's post-plan choice (consult me / run automatically) is a field in the brief [R]; run one = automatic.
- Bosses/managers never do real work; trivial work stays where it lands. Fred must SEE every packet (ledger + packet files); only wake plumbing may be invisible. Rules supersede, never stack; a guard that refuses normal work is a defect; count refusals in the first runs.

## 2. Messaging and waking (✓ = verified)
- Send = append one row to the ledger (`id, from, to, kind, task, headline, path, time`); kinds request/done/question/answer/update; `done` cites its request id. Nothing typed. Boss ledger-only + Herdr notification.
- **Inbox contract** [R]: a row is *received* when the seat's inbox marks it read (at Stop or on wake), *completed* when a `done`/`answer` cites it. Pending (received, not completed) request ids are listed in the seat's handoff; on rotation the new seat inherits them by ack; the old seat stops marking. Test: row arriving during listener re-arm, busy→idle transition, rotation.
- Receiver busy → Stop hook refuses the stop while rows are unread → reads, acts. Receiver idle, Claude → `asyncRewake` listener (armed at SessionStart, re-armed at each Stop; exits 2 on a row) ✓ wakes < 1 s; seat acts only if its card says inbox rows are its work orders ✓. Receiver idle, Codex → one fixed nudge `inbox` via `herdr agent prompt` when `herdr agent get` shows idle/done; **lost-wake window** [S]: if the receiver was `working` at send time, `send` re-checks once after a short delay and nudges if the row is still unread and the seat is now idle (Claude needs none: its re-armed listener catches the row). A failed/stalled nudge is reported by `send`, never retyped. Codex manager waits in the foreground with `--timeout` (deaf for one bounded wait, accepted); parallel workers: one `herdr agent wait` per worker in sequence is fine for v0 (bounded by timeouts).
- **Workers and questions** (Fred, 2026-10-29): a worker sends exactly one kind of row, `question`, to any persistent seat (owner of the thing it needs: its launcher, the tab manager, the architect, research, the helper for environment trouble), in its own words; it then writes `HH:MM question: #id` in its status file and ends its turn. It never waits on anyone, never sends `done`/`update`/`request`, never messages a worker, and never receives a row: its launcher, already waiting on it, sees the status, waits (bounded) for the `answer` row citing the question, and resumes the same worker with one prompt pointing at the answer; if the answer changes the scope, the launcher re-briefs instead. Questions to the launcher itself need no row: the status line is enough. Workers otherwise never message; status file ends `HH:MM done:` / `question:`; manager waits on Herdr (Claude: background `herdr agent wait --timeout`, then ends its turn; Codex: foreground), reads the file; Herdr `done` is never proof.
- Dead/blocked seats: one **detached watcher process** (started by the helper, not an agent turn) [R] on Herdr events `agent_status_changed`/`pane_exited`, appends a `question` row to the orchestrator. Ships in v0 (Fred, 2026-10-29): a detached listener on Herdr `events.subscribe` (`pane.agent_status_changed`, `pane.exited`); on a Kiln seat `blocked` or pane exit it appends one `question` row to the orchestrator. No polling, no retries, no decisions.
- Seat states: acting (working) / waiting (one wait armed, turn ended) / idle. A seat is never `working` while it waits. **Wait contract** [S]: "armed" = a live wait process; its exit (result, timeout, or worker `blocked`) clears it and the manager handles each case: result → read the status file; timeout → decide (extend once, or question up); blocked → read the pane, resolve or escalate. Never re-arm a lifecycle wait when the status file is absent; use a bounded file wait instead.
- Team tool keeps: `send` (append + Codex nudge), `inbox`, `overdue`, ledger. Removed: held queues, admission/confirming, retries, steer-while-working, wake-watch, stuck scans, **and the request-count refusal** [R] (three strikes live in the build manager's card, see §5).

## 3. Hooks (three scripts, shared logic, one adapter per CLI; identity from `seat.json`)
Every hook **exits 0 at once unless the session has a Kiln `seat.json` matching its pane env** [R], so Fred's own sessions and the paused CT101 team never see them.
| Hook | Event | Seats | Checks |
|---|---|---|---|
| stop | Stop (Claude, Codex) | all but agy | refuse only on: unread inbox row; a live worker of mine with **no** wait armed; a finished request with no `done`; a rotation I own not yet acked by the replacement. A pending `question` may stop; honour `stop_hook_active`. [R: "armed wait unfinished" and "new seat must act" removed] |
| fence | PreToolUse | Bash: **bosses and managers only** [R]; writes: **all seats** [R] | Bash: `herdr agent wait`/`pane wait-output` without `--timeout`; Claude foreground wait; typing (`agent prompt`/`send-text`/`send-keys`) into the boss or any pane outside the seat's own workers. No poll-loop regexes in v0. Edit/Write/apply_patch: inside the seat's declared root (workers: their worktree + run folder). Coverage claim scoped [S]: this catches edit-tool writes only; shell writes rely on the family's native write scope (Codex `-s workspace-write -C`, Claude `Edit(//root/**)` rules); no shell parsing, ever. |
| start | SessionStart | persistent seats | inject the card (= handoff/start card): role, root, inbox, parent, pending request ids, open items, "this is enough; read rules/ledger/panes only where an item points you" |
Not shipped: PostToolUse logging, UserPromptSubmit/PostToolBatch reminders, extra PreCompact (keep handoff plugin's), model-switch hooks, subagent/team events, semantic judgments, any agy hook (agy = one-shot headless advisor only [R]). Deny messages phrased per family.
- `seat.json` (launcher-written): name, role, tab, writable root, inbox path, parent, workers, model/effort (from routing), handoff path. **Launcher = executable family contract** [S]: it emits the native flags from the pinned `families.md` (Codex manager: `-s workspace-write -c sandbox_workspace_write.network_access=true`; worker: `-s workspace-write -C <worktree> --add-dir <run>`; Claude: `--model --effort --permission-mode --settings`), installs the hooks for that family, and the first test launches one seat per family in a fresh folder: card received, one permitted write, one Herdr call, resume with the same identity. Herdr `--env` per pane ✓ reaches hooks on all three CLIs. Codex hooks: `.codex/hooks.json` needs one "Trust all" per folder → **test user-level `~/.codex/hooks.json` or a trusted parent before building** [R] (fresh worktree per chunk would otherwise stall on a dialog only Fred may answer).
- Rotation [S]: the handoff plugin's `rotate` keeps its ack-only first turn; **the rotate script publishes the ledger ack from its own receipt** (no duplicate obligation on the new seat), then releases continuation and inbox work; the new seat's start injects the handoff; its stop refuses only on unread rows. Test rotation with an unread row, both families. Handoff plugin (v18) remains the file author; its bootstrap wording that contradicts the new cards is superseded in the release.

## 5. Council tab and fix rounds
Standing manager on Sol med (collects, never judges; the asker owns the ruling [R]); fresh seats per question; conceptual mode (Astra+Fable, Argon parallel) and operational mode (Sol+Opus). Automatic conceptual council at brainstorm close and plan approval; **milestone councils on demand in v0** [R]. Escalation (Fred, 2026-10-29): **three strikes, you are out** (three passes, blocking only, owner routes). A pass = one implementation or fix followed by one review. Pass 1 build→review; pass 2 fix→review; pass 3 fix→review: if the third review still carries a blocking finding, the chunk is escalated (three reviews, two fix rounds, the third verdict decides). A finding is *blocking* only if it cites: a requirement/Done-when of the chunk not met; a reproduction (failing command); a plan-pinned contract or interface violated; a security or data-loss risk. Anything else is minor → `backlog.md`, chunk accepted. **Backlog exits** (Fred, 2026-10-29): (1) the build manager reads `backlog.md` when writing each next brief and folds items touching the same files into that chunk; (2) a backlog chunk clears the rest at the end of each slice; verify accepts a slice only when `backlog.md` is empty or every remaining item is marked `deferred` with a reason; (3) deferred items are listed in `delivery.md` for Fred. The reviewer never escalates, it rejects with its blocking findings. The build+review manager owns the chunk, counts passes in `build.md`, and on the third rejection has Chunk Norris write the five-line note (asked / failed / suspected cause) and routes: brief at fault → re-cuts the chunk itself; plan at fault → `question` to the council (conceptual by default, operational if "it runs wrong"), the manager owns the ruling; council says the plan changes → plan manager writes one ADR in `decisions.md`, re-plans only the affected rows, finished work stands, the chunk returns with a fresh three-pass budget. One message up per step, no new seats.

## 5b. Build tab: Fred's implementing loop (verbatim, 2026-10-27, `bridge/fred-answers.md` §2) + the seats that run it
> A slice is cut into small chunks just in time; each chunk is built test-first, proven by the tests, reviewed by the other model family, and closed only when no checked finding is left open.
> Per chunk: 1 Brief: Chunk Norris writes one brief from the code as it is now; what must be true, never how. 2 Build: a fresh implementer writes a failing test, then the minimum code, until the test passes. 3 Gate: the full check set must pass before any model reads the diff. 4 Review: a reviewer from the other family, with Argon alongside, reports findings and gives no verdict. 5 Check findings: nothing fixed on a reviewer's word alone; a finding a test can show gets a test that fails first; one no test can show goes to the boss. 6 Fix: the same implementer fixes only accepted findings, gate reruns, the same reviewer rereads the fix; [three strikes, §5, supersedes "two fix rounds"]; then split or re-brief. 7 Close: gate passing, nothing open, commit.
> Per slice: first chunk = thin end-to-end path through every layer; later chunks deepen it. Then a simplify audit chunk, then the milestone review, boss decides. At the end: one fresh-user trial runs the real thing.

Seats, three levels (decided B, Fred 2026-10-29: "Chunk Master summons"; each level does as little as possible; as-run CT101 evidence in `/home/dev/.cache/kiln4-fable/codex-buildwiring-kF6AvX/build-wiring.md`, where the manager launched everything and the loop eroded under that load):

| Seat | Lifetime, launcher | Model (balanced) | Inputs | Outputs | Wait |
|---|---|---|---|---|---|
| **Build manager** (address `build`) | standing, launched by the super manager; rotates by the handoff plugin | Opus med | plan (capability list, pinned contracts/interfaces, order), architecture doc, ADRs, `build.md`, `backlog.md`, chunk reports | `slice/<M>/packet.md` (milestone packet), `build.md`, commits on the slice branch, merge to main, one `done` per milestone, escalation rulings | background `herdr agent wait --timeout` on Chunk Master, then ends its turn |
| **Chunk Master** (= Chunk Norris / "Jean-Claude"; address `build-chunkmaster`) | one fresh seat per milestone, launched by the build manager, closed at milestone `done`; manager-class for the fence (may `herdr agent start`) | Sol 6.1 med (Codex) | milestone packet, the code as it is now, architecture doc, `decisions.md`, `backlog.md`; `question` rows to any owner | `chunks/<id>/brief.md`, worker packets, `findings/result.md`, `fix<n>-packet.md`, `decisions.md`, `chunks/<id>/report.md`, milestone `report.md`, `status.txt` | foreground `herdr agent wait --timeout` per worker (one at a time) |
| **Implementer** (`build-<id>-impl`) | fresh per chunk, launched by Chunk Master, kept for the fix rounds (fresh with the fix packet only if past half context) | Sol med, slice worktree + run folder | brief, `decisions.md`, source | failing test → minimum code; `impl/result.md`, `diff.patch`, `status.txt`; never commits | none (ends turn; `question:` per §2) |
| **Gate runner** (`build-<id>-gate`) | fresh per gate run, launched by Chunk Master | Sol low | exact head, check set | `gate/result.md`, logs; evidence only, no edits | none |
| **Reviewer** (`build-<id>-review`) | fresh per chunk, launched by Chunk Master, kept for the re-reads | Opus med for GPT code, Astra med for Claude code; read-only | brief, `decisions.md`, gated diff | `review/result.md`: findings tagged blocking/minor, **no verdict** | none |
| **Argon** | one-shot `agy -p` run by Chunk Master, same snapshot, no reviewer findings shown | gemini-4-argon-high | sanitized brief + diff + tests | `review/argon/opinion.md` | the command itself |
| **Milestone reviewer** (`build-<M>-milestone-review`) | fresh per milestone review, launched by Chunk Master (+ Argon) | other family than the slice's implementers | milestone packet, whole slice diff, Done-when, pinned contracts | `slice/<M>/review<n>/result.md`, findings only | none |

Flow:
1. **Milestone, just in time.** The build manager cuts milestone M from the plan and what is built (first milestone = thin end-to-end path through every layer), writes `slice/<M>/packet.md` (goal, Done-when, pinned plan rows/contracts, pointers to arch doc and ADRs, the `build.md` state line, backlog items touching M), opens the slice branch, launches Chunk Master. A packet that forces Chunk Master to rebuild context by reading the world is a defect of the packet.
2. **Chunks, rolling.** Chunk Master cuts the next chunk only after the previous closed, from the code as it is now: one `brief.md`, what must be true never how, sized for one fresh implementer well under an hour (a chunk that needs more is re-cut). Then steps 2–7 of the loop above, each step one worker, gate before any model reads the diff, Argon alongside every review, findings checked test-first (a finding no test can show goes to the owner by `question`), same implementer fixes, same reviewer rereads, three strikes counted in `decisions.md`. Close = `report.md` to the manager (`done` row); the manager commits the exact files on the slice branch and appends `build.md`.
3. **Milestone end.** After the last chunk: the tidy chunk (simplify audit, same loop), then the milestone review (reviewer + Argon on the whole slice diff against Done-when and pinned contracts). Blocking findings (§5 definition) become fix chunks through the normal loop, then one re-review of the delta; review → fix → re-review → fix → re-review: a blocking finding on the third review is the third strike, Chunk Master writes the five-line note and the manager routes as in §5. Minor → `backlog.md`; the backlog chunk clears it before `done`; verify accepts only with an empty or all-deferred backlog.
4. **Done.** Chunk Master sends `done` with the milestone report; the manager merges the slice branch to main, writes one `done` up, cuts M+1, launches a fresh Chunk Master. The fresh-user trial runs once at the end of the plan, launched by the manager.
5. **Questions** go to owners directly (§1, §2): Chunk Master → architect/research/manager; workers → any owner, relayed by Chunk Master. Three-strikes escalation stays the manager's (§5).
- Parallel chunks only with disjoint files, one Chunk Master per parallel chunk, same milestone packet; v0 runs chunks serially.
- Files: `build/slice/<M>/{packet,report}.md`, `build/slice/<M>/review<n>/`, `build/chunks/<id>/{brief,decisions,report}.md, impl/, gate/, review/, findings/, fix<n>-packet.md, status.txt`; `build.md`; `backlog.md`.
- Fixed names: Gravedigger (helper) and Chunk Master / Chunk Norris. All other display names are the boss's choice (§1).
