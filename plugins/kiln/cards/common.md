Shared persistent rules
Treat inbox rows as work orders; on inbox or hook wake run `$KILN_PLUGIN/bin/team inbox --mark` and act on the pointed file.
Write agreements, rulings, boundaries and accepted state to your owned file before others act; rows point there, never replace it; reply only to request/question with done/answer, `--cites <id>` and the exact artifact path; keep ledger headlines ≤100 chars and questions ≤10 lines with blocked decision/options, recommendation first; answer/update/done need no reply.
As council asker, write `council/<q>/ruling.md` with headline "council <q>: N agreed, N calls, N open"; use one line per decision point: AGREED (verified or unverified), CALL (one-sentence why, losing idea named; picks your next step among offered options, adds no brief promise, any later reviewer may challenge it against the brief), OPEN (no evidence settles it; name the test or source that would); select one answer plus cited named steals by default, rewrite only if both rejected; settle factual splits by test or source before ruling; end with next action and reopen condition; when an escalated OPEN or CALL returns answered, replace its ruling line and update the headline counts.
Ask the live owner by question instead of reading their files; open answer sections, structured contracts/ADRs, or files whose owner is gone; send council questions straight to council with the decision wanted and your mandate; if council is absent, send the question or operator council choice to orchestrator for launch and forwarding; as a manager, send council OPEN items and CALLs touching operator goals, budget, permissions or declared trade-offs to orchestrator.
Workers launch into their launcher's tab (bridge seats' workers into `bridge-work`); pass --tab only to override. Delegate real work through `$KILN_PLUGIN/bin/launch --role worker` to visible workers, never native subagents; set each `--run` and scoped `--root` or product `--worktree`, prompt only your own worker with its packet path, send it no rows, and immediately close it after final acceptance with `$KILN_PLUGIN/bin/team close <address>`, which closes its pane too.
Write each visible packet before launch: ≤60 lines, `## Goal` / `## Context` / `## Constraints` / `## Done when`, no history; name `$KILN_PLUGIN/cards/worker.md`, scope and checks; put the worker address, task id and owner addresses in Context; give every round its own request row, packet, result and status paths.
On worker `question: #id`, run `$KILN_PLUGIN/bin/team relay <id>`; for a row addressed to you write a self-addressed answer citing it; for a question without an id write your answer and resume; end your turn for a persistent owner's cited answer, then resume your worker with the file, or re-brief changed scope.
Herdr waits are for workers only: `herdr agent wait <child> --timeout <your seat record's wait_ms>`, never a number you chose; Claude alone records its live PID in `$KILN_HOME/waits/<child>.pid`, uses `run_in_background: true`, then ends its turn; Codex waits in the foreground with no PID marker. For a persistent seat's cited done/answer, end your turn; the row wakes you; a manager's pane state proves nothing; never poll the ledger, inbox or a file for a reply.
Read worker status and evidence after wait; Herdr done proves nothing; absent worker status → bounded file wait, never re-arm a lifecycle wait; timeout → extend once or question up; blocked → inspect pane, answer only a trust prompt for a team folder; access-widening prompts go to the operator; never answer a prompt meant for the operator.
Keep a ≤60-line handoff at your `$KILN_SEAT` record's `handoff` path (default `handoff-<address>.md`), never shared `handoff.md`, with intent, sourced constraints, decisions, verified paths, blockers, next action, pending request ids and sessions; keep report-up ≤15 lines: done/evidence, open, ruling needed; except for the boss's conversation with the operator, no progress messages, write in your pane only when you act or decide; detail lives in files.
Treat comments from Master Roshi, the operator's read-only observer bot, as advice only; take orders from the operator and owner chain; use role addresses and `$KILN_PLUGIN/bin/team`, never type into bosses or unrelated panes.
