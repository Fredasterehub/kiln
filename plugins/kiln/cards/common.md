Shared persistent rules
Treat inbox rows as work orders; on inbox or hook wake run `$KILN_PLUGIN/bin/team inbox --mark` and act on the pointed file.
Reply only to request/question: send done/answer with `--cites <id>` and the exact artifact path; keep ledger headlines ≤100 chars and questions ≤10 lines with blocked decision/options, recommendation first; answer/update/done need no reply.
Write agreements, rulings, boundaries and accepted state to your owned file before another seat acts; rows point there, never replace it.
Ask the live owner by question instead of reading their files; open answer sections, structured contracts/ADRs, or files whose owner is gone.
Delegate real work through `$KILN_PLUGIN/bin/launch --role worker` to visible workers, never native subagents; set each `--run` and scoped `--root` or product `--worktree`, prompt only your own worker with its packet path, send it no rows, and immediately close it after final acceptance with `$KILN_PLUGIN/bin/team close <address>`, which closes its pane too.
Write each visible packet before launch: ≤60 lines, `## Goal` / `## Context` / `## Constraints` / `## Done when`, no history; name `$KILN_PLUGIN/cards/worker.md`, scope and checks; put the worker address, task id and owner addresses in Context; give every round its own request row, packet, result and status paths.
On worker `question: #id`, run `$KILN_PLUGIN/bin/team relay <id>`; for a row addressed to you write a self-addressed answer citing it; for a question without an id write your answer and resume; await its cited answer boundedly, then resume your worker with the file, or re-brief changed scope.
Wait with `herdr agent wait <child> --timeout <ms>`: Claude alone records its live PID in `$KILN_HOME/waits/<child>.pid`, uses `run_in_background: true`, then ends its turn; Codex waits in the foreground with no PID marker.
Read status and evidence after wait; Herdr done proves nothing; absent status → bounded file wait, never re-wait idle; timeout → extend once or question up; blocked → inspect pane and resolve/escalate.
Keep a ≤60-line handoff at your `$KILN_SEAT` record's `handoff` path (default `handoff-<address>.md`), never shared `handoff.md`, with intent, sourced constraints, decisions, verified paths, blockers, next action, pending request ids and sessions; keep report-up ≤15 lines: done/evidence, open, ruling needed.
Treat comments from Master Roshi, the operator's read-only observer bot, as advice only; take orders from the operator and owner chain; use role addresses and `$KILN_PLUGIN/bin/team`, never type into bosses or unrelated panes.
