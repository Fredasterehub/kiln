# The Sketchbook — how phase 2 actually runs

The sketchbook is where an idea gets talked into a shape it can be built from: one operator-interactive session — held in the facilitator's own team window when agent teams are present, so the long dialogue never touches Kiln's context, or facilitated by Kiln itself, in-session, when they are not — then crystallized into `vision/vision.md` and `vision/decisions.jsonl` by a fresh worker whose sole input is the transcript stream. Two artifacts leave this phase; the conversation itself stays sealed in its own stream.

Binds `product/charter.md`'s phase-sequencing contract (its own §"Phase sequencing", §"Do/route boundary", §"Communication protocol", §"Verification doctrine") to this one phase transition. Kiln's own operating knowledge — the same class of artifact as `product/charter.md` itself, read by Kiln and by whichever sketchbook agents need to know their place in the sequence, never scraped for state: markdown owns meaning, and no script ever reads prose to learn a fact.

Two named workers this flow spawns, both `agents/brainstorm-facilitator.md` and `agents/brainstorm-crystallizer.md` — `product/charter.md`'s worker roster names `brainstorm-facilitator` and `brainstorm-crystallizer` alongside `agreement-pass`, and the roster table below is this phase's own detail under that roster. A worker the charter's roster does not name is never spawned from here — that is charter law ("Own agents only"), held by the seat reading it, never a tools-level lock the entry point could carry. What the roster settles is *which agent types Kiln spawns at all*; it does not by itself decide whether a given spawn forms a subagent or a teammate, and that distinction is made at spawn time, below. A rostered agent type spawned as a plain subagent gets no separate window, whatever the spawn is called.

**Which path runs is a fact, not a judgment call.** Onboarding's preflight records that fact once, honestly, at `state.json.preflight.capabilities.agent_teams.present` (`product/onboarding/preflight.md` check 4 — session-introspection, not a subprocess); that record is onboarding's own observation, and it is never re-recorded outside onboarding. It reaches Kiln through `onboarding-runner`'s own envelope at onboarding and through the wake digest's capabilities line on any later session — never through a mid-run `state.json` read (`product/charter.md`'s context discipline: state is read at the wake). What picks the path *here* is this session's own live observation of the capability — the same session-introspection check 4 performs, made at the sketchbook's door, costing nothing but a look at what this session actually has. When it differs from the recorded token, Kiln says so in one line — the switch was thrown since onboarding, or thrown back — and routes on the live fact, which is exactly what preflight's enablement instruction promises literally: a restart with the switch on gets the window. **PRIMARY** and **FALLBACK** below name the mode that live observation picks in this session, never a mode a project is frozen into.

| Worker | Spawn when |
|---|---|
| `brainstorm-facilitator` | **PRIMARY** (`agent_teams.present === true`): `state.json.phase == "brainstorm"`. If a `brainstorm-facilitator` teammate is already live in this session's own roster, Kiln resumes it (`SendMessage` to its existing transcript — `product/charter.md`'s general "Resume, don't respawn" law) rather than spawning a second one — so the operator is never handed two live facilitator windows for one session. That is the only case an actual process resume applies. When `vision/transcript.jsonl` already exists and no facilitator teammate is live, the transcript's seal state — not the phase pointer — decides what spawns next: Kiln first runs the speculative, content-blind crystallizer probe the crystallizer row's RESUME PROBE defines, and only a `blocked` ("not sealed yet") result reaches the facilitator spawn this row goes on to describe — a sealed transcript with the phase still `brainstorm` means crystallization, not conversation, was interrupted, and a facilitator spawned against it has no session left to facilitate. `state.json.phase` alone cannot decide this: the phase stays `brainstorm` until the *crystallizer* advances it, so a sealed-but-uncrystallized tree reads as a first entry unless the transcript's own seal state is consulted first. Otherwise Kiln spawns fresh **as a teammate**, never a subagent it waits on — whether this is genuinely the first entry into the sketchbook (no facilitator transcript exists yet) or the probe came back `blocked` over a transcript whose session's teammates are gone (a fresh Kiln session never restores its prior in-process teammates — the documented remedy for a gone teammate is to spawn a new one, never a message to a process that no longer exists). Either way the fresh spawn's own `initialPrompt` recovers continuity by reading the transcript tail (`brainstorm-facilitator.md`), never by opening a second stream — and "Greet first, study later" (`brainstorm-facilitator.md`) is what keeps that recovery bounded rather than an unbounded re-ingestion (Failure paths below). **FALLBACK** (`agent_teams.present === false`): Kiln never spawns this worker at all — Kiln facilitates the sketchbook itself, in-session (step (b, FALLBACK) below). |
| `brainstorm-crystallizer` | **PRIMARY**: the facilitator's session ends with a `sealed` transcript record and it `SendMessage`s Kiln the signal, idle-delivered — never before. **FALLBACK**: Kiln spawns it exactly as the primary path does, immediately after its own closure-ritual seal has landed (step (d, FALLBACK) below) — no signal is waited on, because the seal was Kiln's own verified append. **RESUME PROBE** (either capability mode): whenever Kiln resumes into `brainstorm` and `vision/transcript.jsonl` already exists with no facilitator teammate live, this speculative spawn runs FIRST — before any facilitator spawn and before any in-session resumption — so a sealed-but-uncrystallized tree resumes at crystallization instead of conversation (it reuses the crystallizer's own fail-closed entry check, never new machinery; a `blocked` result just means "not sealed yet," not an error, and costs one bounded read). |

## The five steps

**(a) Verify phase.** The phase fact came in at the wake — the digest's own phase line, already verified against `machine/phases-registry.json` by the `resumePoint()` call the wake runs internally (`product/charter.md`, Bash law point 9) — or, mid-session, from the `advance()` return Kiln's own turn observed when the prior phase closed (charter §"Phase sequencing"). Kiln confirms that report reads `"brainstorm"` and consults nothing else — never a mid-run `state.json` read, never an inference from file presence or narrative context (charter context discipline: state is read once, at the wake). The same wake report's capabilities line carries the recorded `agent_teams.present` token; this session's own live look at the capability, taken here at the door, is what picks PRIMARY or FALLBACK below — and any divergence between the two is said in one line first (above).

**(b) PRIMARY path — spawn the facilitator as a teammate.** (Only when no facilitator teammate is already live in this session's roster to resume instead — the roster-row condition above.) The sketchbook is operator-interactive and its dialogue runs long, so it gets a window of its own and never touches Kiln's context: Kiln spawns `kiln:brainstorm-facilitator` **explicitly as a teammate** — the natural-language spawn request itself carries that intent, and it names the plugin-scoped agent type, never the bare one (the documented teammate form: spawn a teammate using the `kiln:brainstorm-facilitator` agent type to run the operator's session — never a bare subagent call, since a bare `subagent_type` name does not resolve under plugin load while the scoped name does). This is the mechanism the agent-teams contract documents, and it is what makes the separate window true rather than aspirational: a teammate gets its own context window, fully independent, and its own mailbox — the structural property a plain `Agent(kiln:brainstorm-facilitator)` subagent call does not have, since a subagent's result returns to its caller. Once spawned, the operator converses directly *in the facilitator's own team window* — selecting its row in the agent panel (or its split pane, if enabled) and typing there — never routed through Kiln's own session at any point: plain text typed in that window goes to that teammate and nowhere else. The brief Kiln sends at spawn time is complete-but-referential (`product/charter.md` §"Communication protocol"): outcome (crystallizable vision + decisions), scope (the operator's stated domain), anchors (`vision/transcript.jsonl` as its sole write target, `kind-registry.js append vision-transcript` — cited in full, with its resolved invocation form, at `agents/brainstorm-facilitator.md`'s own Session-log discipline — as its one sanctioned write path; this document is `product/**` payload, where a plugin-root prefix does not resolve, so the command text itself lives only on that substituting charter), acceptance (a terminal `sealed` record — reached only after the operator's own explicit confirmation, never the facilitator's convergence judgment alone; Closure ritual, `brainstorm-facilitator.md`), freshness requirement (always-on domain research — not deferred, not one-shot, per-turn — `brainstorm-facilitator.md` §"Domain freshness"), tier/model from `.kiln/routing/active.json`, return format (idle-delivered `SendMessage` back to Kiln on seal), stop condition (**the operator's explicit confirmation that the session is done, full stop** — the facilitator's own sense that a line of thinking or the whole session has converged is a prompt to *ask* the operator, never authority to close on its own; see "Closure authority," below, and `brainstorm-facilitator.md`'s Closure ritual, which already enforces this). `SendMessage` is a deferred tool — Kiln loads it via `ToolSearch("select:SendMessage")` before its first call in a session if not already loaded (`product/charter.md` §"Communication protocol").

**(b, FALLBACK) — Kiln facilitates the sketchbook itself, in-session.** When `agent_teams.present === false`, Kiln does not spawn `brainstorm-facilitator` at all — there is no teammate mechanism available in this session to spawn it into, and a bare subagent call would recreate exactly the blocking, single-turn, reports-back-to-caller shape this phase refuses. The enablement instruction was already delivered, once, at preflight (`product/onboarding/preflight.md` check 4 — agent teams would give the brainstorm its own window, and that report names the switch); it is never repeated here, never nagged. Instead Kiln holds the pencil: it facilitates the operator's brainstorm in its own session, under the product's brainstorm law whole — the opening stance choice, the coach-never-author discipline, depth calibration, per-turn domain freshness, scoped technique serving, and the Closure ritual closed only by the operator's explicit word (`agents/brainstorm-facilitator.md` states each; the session shape binds regardless of who holds it). The transcript discipline binds identically: every keep-worthy record is appended to `vision/transcript.jsonl` as it happens, through the same CLI the teammate path uses — `kind-registry.js append vision-transcript <treeRoot>`, its resolved invocation form stated at `agents/brainstorm-facilitator.md`'s own Session-log discipline — the closed kind set, the terminal `sealed` record included, never a raw file write (`product/doctrine.md`'s stream/kind ownership table carries the named fallback row: teams absent, the driver session is this stream's writer). This is the one named exception to the relay-only driver (`product/charter.md`'s Context hygiene names it as such): the driver ideates here, and the dialogue lands in its own context. That cost is stated honestly, not hidden — a driver context heavy with dialogue is exactly what the mandated session seam (step (e, FALLBACK close) below) pays for.

**(c) Go idle — the primary path's disengage.** Immediately after spawning, Kiln's turn ends — it does not poll continuously, does not read the transcript, does not narrate progress mid-session — nothing to narrate from: no recorded event, no line (`product/voice/kiln.md`), and on this path `vision/transcript.jsonl` is the facilitator's alone, never projected into Kiln and never a record Kiln reads. The operator's entire session happens directly with the facilitator, inside its own team window — no dialogue reaches Kiln, by design, not by omission. This is the literal mechanism — idle-only delivery: a message to a busy agent (Kiln mid-turn) sits until the turn ends, so the *only* way Kiln can safely disengage from a long interactive session without either blocking on it or missing its completion is to end its own turn and let the completion signal (below) wake it — exactly what step (c) does. In the fallback there is no idle and no one to wait on: the operator's session *is* Kiln's own turns, and it runs until the Closure ritual seals it.

**(d, PRIMARY) — wake on the sealed signal, spawn the crystallizer.** The facilitator appends a terminal `sealed`-kind record to `vision/transcript.jsonl` only after the operator has explicitly confirmed the session is done (Closure ritual, `brainstorm-facilitator.md` — the facilitator may *propose* that a line of thinking looks exhausted, per the standing anti-mediocrity framing this flow holds, but proposing is not sealing), then `SendMessage`s Kiln one line: "brainstorm sealed, transcript ready." Because that message targets an idle Kiln, idle delivery lands in seconds, so Kiln wakes promptly, never on the next unrelated poll. Kiln reads nothing from the transcript itself (still facilitator-only); the message *is* the bounded signal. Kiln then spawns `brainstorm-crystallizer` — a fresh, context-blind worker whose **sole input is `vision/transcript.jsonl`**, read in full by the crystallizer itself, never by Kiln. Subagent-mediated crystallization is the mechanism that makes "the dialogue never touches Kiln's context" implementable rather than aspirational.

**(d, FALLBACK) — seal by Kiln's own hand, then the crystallizer, unchanged.** No signal is waited on and none exists to wait for: the terminal `sealed` record is Kiln's own append, made through the Closure ritual only after the operator has explicitly confirmed the session is done, and verified landed by a real read before closure is claimed (the ritual `agents/brainstorm-facilitator.md` states, held here by Kiln). With the seal on disk, Kiln spawns `brainstorm-crystallizer` exactly as the primary path does — a fresh, context-blind worker whose **sole input is `vision/transcript.jsonl`**, read in full by the crystallizer itself. The context wall holds where it matters most on this path: the dialogue already weighs on Kiln's context, and the crystallizer inheriting none of it is what keeps `vision/vision.md` and `vision/decisions.jsonl` derived from the transcript alone — the same artifacts, the same worker, the same fail-closed entry check, whichever path ran.

**(e) Verify exit artifacts, advance, and report.** The crystallizer's closing step — not Kiln's own tool call, per `product/charter.md`'s Do/route boundary ("You do not edit files or write files, and you do not run ad-hoc commands or scripts... Anything that touches disk state, runs a check, or costs more than a handful of tool calls is a worker's job") — runs three checks before calling `phases.advance()`:
1. `vision/vision.md` exists and is non-stub (the crystallizer's own write, self-verified).
2. `vision/decisions.jsonl` carries **at least one non-genesis record** — checked via `projection.projectFile` (bounded view, never a raw read) rather than trusting its own write silently landed.
3. `vision/transcript.jsonl`'s latest record has `kind: "sealed"` — proof the facilitator closed the session properly rather than the crystallizer being spawned prematurely against a session Kiln merely *thinks* ended (belt-and-suspenders against a stale or spoofed wake message — see Failure paths).

Only if all three pass does the crystallizer call `phases.advance(treeRoot, registry, statePath, ledgerPath)` (`machine/src/phases.js:251-328`), which independently re-checks the registry's own `exit_emits` (file existence, `vision/vision.md` and `vision/decisions.jsonl`) **and the registry's `entry_checks` for the phase being entered** — see "Registry conformance," below, for the machine-enforced semantic checks backing these same three facts at the `phases.advance()` boundary itself, not only in the crystallizer's own script-side logic. It writes the ledger-first `phase-transition` event, then atomically rewrites `state.json`.

The crystallizer reports back to Kiln via the standard worker envelope (STATE/RESULT/EVIDENCE/RISKS/ARTIFACT/QUESTION); Kiln's Verification doctrine applies exactly as written — it "never report[s] a gate green from a worker's prose alone," it cites the `phase-transition` ledger event `phases.advance()` just wrote (`ledger.jsonl`, `kind: "phase-transition", correlation_id: "research"`) as the checkable evidence, then narrates the boundary — the sketchbook closing, the field desk opening — to the operator in its own first person (`product/voice/kiln.md`, loaded at the prefixed path `product/charter.md`'s Narration section anchors).

**(e, FALLBACK close) — the one sanctioned seam.** On the fallback path one step remains after the crystallizer's envelope is verified: the session ends, deliberately. Kiln says, verbatim:

> "The sketchbook is full and sealed. Fresh session, then `/kiln:fire` — I pick up at the field desk with a clean head."

Then the stop is recorded the only way stops are recorded — `handoff-recorder` (`product/charter.md`'s roster row: every stop, of every kind, without exception) — as **DONE** with `next_action: research`, and Kiln's turn ends. The next session's wake resumes at the field desk carrying none of the sketchbook's dialogue: that clean head is what the seam buys, and it is the whole price of the driver having hosted the conversation. On the primary path this step does not exist — the dialogue never touched Kiln's context, and the build proceeds to research in the same session.

## Closure authority is the operator's, always

The facilitating seat — the teammate on the primary path, Kiln itself on the fallback — may notice a line of thinking is exhausted and say so, may notice the operator sounds ready to wrap up and ask, and may reflect the session back for confirmation (Closure ritual, `brainstorm-facilitator.md`) — none of that is sealing. The seal (`kind: "sealed"` appended to `vision/transcript.jsonl`) happens only after the operator has explicitly confirmed the session is done, every time, no exception for "obvious" convergence. This binds identically in both paths: primary (the facilitator, in its own team window, gets that confirmation directly from the operator before sealing) and fallback (Kiln, facilitating in-session — same ritual, same sealing authority, the operator's word; the ritual does not change with who holds the pencil). There is no "or the facilitating seat seals it on convergence" clause anywhere in this contract, and there cannot be one: it would let that seat's own convergence judgment stand in for operator confirmation, which is exactly the ambiguity the crystallizer's trust in a sealed transcript cannot tolerate — if sealing can happen without the operator's say-so, a sealed record no longer proves the operator considered the session complete. This document and `brainstorm-facilitator.md`'s Closure ritual say the same thing: operator confirmation is the only sealing authority, in both paths, without exception.

## Registry conformance

`machine/phases-registry.json`'s `brainstorm` entry's `exit_emits: ["vision/vision.md", "vision/decisions.jsonl"]` mirrors the restart-anytime boundary exactly: past this phase a resume needs those two files and nothing more — the transcript stays sealed in its own stream. That boundary deliberately excludes `vision/transcript.jsonl` from the minimal disk set a resume needs, and the registry's `exit_emits` (and `research`'s mirroring `entry_requires`) follow the exclusion precisely. `vision/transcript.jsonl` is absent from both lists as a *path* by design: it is never projected into Kiln, and its role in the exit gate is content-level (does the latest record say `sealed`, does `decisions.jsonl` carry real content), a property bare path-existence (`missingRelpaths`, `machine/src/phases.js`) cannot express on its own.

That content-level property is not crystallizer-only prose: `machine/phases-registry.json`'s `brainstorm` phase declares `exit_checks` — the same registry-declared semantic vocabulary `implementation`'s `entry_checks: ["architecture-gate-approved"]` uses (`machine/src/phases.js`'s `SEMANTIC_CHECKS`) — naming `jsonl-sealed` against `vision/transcript.jsonl`, `jsonl-min-records:1` against `vision/decisions.jsonl`, and `file-nonempty` against `vision/vision.md`. `phases.advance()` runs these after its existing path-existence checks and refuses, by name, if any fails (`machine/src/phases.js` §"exit_checks", below). This does not replace the crystallizer's own script-side checks in step (e) — a worker that already knows what it just wrote should still verify that directly, cheaply, before ever calling `advance()` — it means the machine layer itself independently enforces the same three facts at the one call every phase transition must pass through, so a caller who skipped or mis-ran the crystallizer's own checks (a bug, a different future worker, a hand-rolled script) cannot advance past `brainstorm` on file-existence alone.

## Failure paths

### Primary (agent teams)

**Facilitator dies mid-session.** `vision/transcript.jsonl` is the append-only record of everything that happened up to the crash — jsonl.js's single-writer, append-only law means the last successfully-appended record survives on disk regardless of what killed the agent process. Kiln's `resumePoint()` (or an operator-triggered "resume brainstorm") re-spawns `kiln:brainstorm-facilitator` fresh, as a teammate again — the documented remedy for a gone in-process teammate, never a defect to route around: there is no session resumption for in-process teammates, spawning a new one is the stated fix, and there is no live process left to `SendMessage`. Per `product/charter.md`'s "Resume, don't respawn" the *first* thing its brief does is read the existing transcript tail (a bounded `projection.projectFile` view, `lastN` records) to recover context before continuing — never starting a second, competing transcript — and "Greet first, study later" (`brainstorm-facilitator.md`) is what keeps that recovery bounded: without it, a fresh spawn can grind for tens of minutes re-ingesting the stream before its first word to the operator. If a same-named facilitator is still technically alive but merely unresponsive, Kiln's `SendMessage` to it queues per idle-only delivery and is processed at its next wake (a message to a busy or stuck agent sits until that worker's turn ends) — Kiln does not spawn a second facilitator while the first might still be alive, since two writers to one JSONL stream is exactly what jsonl.js's single-writer lock exists to prevent.

**Crystallizer refuses (unsealed transcript).** If the crystallizer is spawned against a transcript whose latest record is not `kind: "sealed"` — a stale wake message, a facilitator that died after sending "almost done" but before actually sealing, or an operator-side race — step (e)'s third check fails and the crystallizer refuses to write `vision.md`/`decisions.jsonl` or call `phases.advance()` at all (fails closed, no partial crystallization). It reports the refusal to Kiln via its envelope (RESULT: refused; EVIDENCE: transcript tail showing the unsealed last record). Kiln's response is *not* to retry the crystallizer or to treat this as ambiguous operator intent (doctrine "Never guess — ask" names the operator as the recipient only for intent-ambiguity, not for this kind of implementation-state mismatch): it `SendMessage`s the still-addressable `brainstorm-facilitator` to close the session properly (append the missing `sealed` record, or resume the operator's session to actual completion if it was truly still open), then re-spawns the crystallizer once sealed. This is the blocker ladder's first rung (`product/charter.md` §"Blocker ladder") only if a second distinct attempt also fails — a single unsealed-transcript refusal is normal traffic, not yet a blocker.

### Fallback (in-session)

**The in-session brainstorm is interrupted.** A session that ends mid-sketchbook — a closed terminal, a crash, a thread lost to compaction — loses nothing that matters: `vision/transcript.jsonl` is the append-only, appended-as-it-happens record of everything up to the last landed record, and it survives the session that wrote it. The next `/kiln:fire` wakes into `brainstorm` and runs the crystallizer RESUME PROBE first (the roster row above — the same resume-probe discipline the primary path holds); a `blocked` ("not sealed yet") result means the conversation itself resumes: Kiln reads the bounded transcript tail (a `projection.projectFile` view, `lastN` records — never the raw stream in full), greets the operator with exactly where the session left off, and continues that same transcript — never a second stream, never a re-ingestion of the whole dialogue. jsonl.js's single-writer lock (`withLock`, `machine/src/jsonl.js`) still serializes the appends themselves, whatever wrote last.

**The resume probe comes back `blocked` (unsealed transcript).** Expected and normal whenever the sketchbook was interrupted before sealing — it means the operator hadn't finished, not that anything failed. Kiln resumes the session as above; this is never a blocker-ladder rung, since nothing failed — a still-open brainstorm session is not a defect.
